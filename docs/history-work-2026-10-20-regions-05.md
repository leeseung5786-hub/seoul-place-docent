## 작은 기능 구현·배포

- `verify-region-lifecycle`은 등록 ID·현재 코드·현재 리비전만 받는다. 검토된 불변 스냅샷에서 전체 명칭과 코드·상태를 찾으며, 호출자가 상태·출처를 임의로 공급할 수 없다. 먼저 주소 응답 대조가 있어야 한다.
- 코드 상충 시 기존 코드를 덮어쓰지 않고 별도 상태로 남긴다. 명칭 불일치·중복·잘못된 원문은 저장하지 않는다. 리비전 충돌을 거절하고 검토·감사 기록을 같은 트랜잭션으로 추가한다. 기존 주소 검토는 그대로 유지한다.
- 기존 검토 테이블을 재사용했다. 스키마와 적용된 마이그레이션은 변경하지 않았다. 임의 SQL·삭제·초기화 기능을 추가하지 않았다.
- 주소 응답 대조와 현존·폐지 확인을 방법별로 독립 집계하고 확보 현황 화면에 분리 표시했다. 현존 상태를 역사본문 내용 검토 완료로 표시하지 않는다.
- 개별 테스트 105개, 타입 검사 `tsc --noEmit --incremental false`, 빌드, diff 검사를 통과했다. 실행 플래그와 변환·격리 설정 문제는 수정한 명령으로 재실행했다. 파일 단위 9개 통과를 105개 문항 통과와 혼동하지 않았다.
- 앱 커밋 `8e456c8367bb5bd48387508cbfbd85b2caef27dd`를 기존 사이트 version 18로 배포했다. 배포 ID `appgdep_6ad7472c16448191b356b4a49a6b5da5`, 결과 `succeeded`. 소유자 전용 정책이 유지됐다.
- 관리형 미리보기는 실행 중으로 보고됐으나 클라우드 브라우저에서 `ERR_CONNECTION_REFUSED`가 발생했다. 상태 확인 후 미리보기를 중지했다. 브라우저 시각 검증·전체 주소 흐름 검증을 완료했다고 보고하지 않는다. 이 한계는 API·단위 테스트·빌드 검증과 별개다.

- 처리 ID 50개와 주소·현존 검토 ID·리비전·코드·시각·근거 해시는 `data/region-code-observations-2026-10-20-mapo-seongdong-05.json`에 남겼다. 데이터 변경 후 추가 앱 재배포는 필요하지 않다. 마지막 작업 기록과 영수증은 소스로 동기화한다.
